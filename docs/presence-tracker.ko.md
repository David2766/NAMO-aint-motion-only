# 재실 트래커와 센서 융합

이 문서는 필터링된 LD2450 관측값에서 최종 재실·움직임 출력까지 이어지는 현재
production 경로를 설명합니다.

## 1. 런타임 경로

- 트래커 경로가 기본값입니다. 기존 lambda 경로는 고급 설정의 legacy 재실 옵션을
  통한 명시적인 fallback으로 남아 있습니다.
- 500ms ESPHome lambda는 필터링된 최신 LD2450 프레임, PIR 상태, 방/퇴실 근거와
  선택적인 LD2410C 근거를 C++ 컴포넌트로 전달합니다. LD2450 프레임 세대는 한 번만
  소비하므로 오래된 센서 상태를 여러 관측으로 반복 계산하지 않습니다.
- `PresenceTracker`는 LD2450 track identity, 생명주기, 위치, 속도, 방향, 방 경계
  통과와 퇴실 근거를 소유합니다.
- `PresenceFusion`은 PIR과 트래커 근거를 결합하고, 선택적인 LD2410C는 PIR 또는
  확정된 LD2450 트랙이 이미 시작한 세션을 유지할 때만 사용합니다.
- 출력은 `/api/state`, Home Assistant 엔티티, 진단 및 리플레이 로그에 노출됩니다.

## 2. LD2450 추적

트래커는 LD2450 하드웨어 한도에 맞춰 관측값과 유지 중인 트랙을 각각 최대 3개
처리합니다. 일반적인 Hungarian 구현 대신 가능한 작은 assignment 조합을 직접
평가합니다.

트랙 상태는 다음과 같습니다.

- `tentative`: 최근 관측 횟수가 충분해질 때까지 대기합니다.
- `confirmed`: 재실과 움직임/정지 개수에 직접 반영됩니다.
- `coasting`: 관측이 사라진 뒤 제한된 시간 동안 유지됩니다.
- `idle`: 사용하지 않는 슬롯입니다.

위치와 속도는 시간 간격, process noise, measurement noise와 covariance를 제한한
등속도 Kalman filter를 사용하며 LD2450 수준의 좌표 불확실성을 반영합니다. 순간 이동에
가까운 큰 관측이 한 번 들어오면 마지막으로 승인된 위치를 유지한 채 재배치 후보로만
기록합니다. 제한 시간 안에 가까운 위치가 한 번 더 관측되어야 새 위치에서 속도를
초기화하고 트랙을 다시 연결합니다. confirmed/coasting 트랙은 새 tentative 트랙보다
넓은 재연결 범위를 사용합니다.

`trackScore`는 최근 hit, miss와 생명주기 상태에서 계산한 진단 점수입니다. 확률이나
사용자용 신뢰도 퍼센트가 아닙니다.

### LD245x 수신 우선 시작

로컬 LD2450 parser는 LD2450과 LD2454가 공유하는 주기 좌표 frame을 처리합니다. 부팅 후
3초 동안 먼저 유효 frame을 기다리므로 이미 정상 송신 중인 레이더를 추측으로 재시작하거나
조회하지 않습니다. 이 시간 안에 frame이 없으면 단 한 번의 제한된 복구 transaction을
시작합니다. 정상 경로와 복구 경로 모두 두 모델의 문서에 있는 설정 진입, 필요한 경우 최초
1회의 다중 타깃 설정, firmware version 조회, 설정 종료만 수행합니다. 각 명령은 일치하는
성공 ACK를 받은 뒤에만 다음 명령으로 진행합니다. 거부 또는 timeout이 발생하면 설정 종료를
한 번 시도한 뒤 반복 재시도 없이 끝냅니다. 진단에는 원시 RX byte와 유효 frame, 잘못된
frame, parser 초기화 횟수를 남깁니다. API frame guard는 입력 누락과 정지만 기록하며 레이더
명령을 보내지 않습니다.

### 타깃별 필터 admission

하드 필터와 보정 필터 판정은 각 LD2450 타깃이 트래커 상태를 갱신하기 전에
개별적으로 적용합니다. 차단된 관측은 기존 오탐 트랙을 정확히 찾아 숨기고 노화시키기
위한 좌표 연관에만 사용할 수 있습니다. 새 트랙 생성, 기존 트랙 갱신 및 출력에는
사용하지 않습니다. 같은 프레임의 차단되지 않은 다른 타깃은 거리 admission과 추적을
계속 진행합니다.

전역 `filter_blocked` 보호는 하나 이상의 타깃이 관측되었고 관측된 타깃 전부가
차단되었을 때만 활성화합니다. 완전히 필터된 프레임에 대한 기존 융합 및 LD2410C
보조 veto는 유지하면서 오탐 하나가 실제 타깃까지 차단하지 않게 합니다.

## 3. 퇴실 및 방 근거

각 트랙은 최근 퇴실 지점 진입과 방 경계 상태를 기록합니다.

- 최근 설정된 퇴실 지점을 지난 트랙은 coasting이 짧아지고
  `lost_after_exit`으로 종료될 수 있습니다.
- 신뢰할 수 있는 방 안쪽에서 바깥쪽으로의 경계 통과는
  `lost_after_room_exit`이 될 수 있습니다.
- 두 근거 없이 사라지면 `lost_without_exit`이 되고 더 긴 비퇴실 coasting 정책을
  사용합니다.
- 모든 관측이 필터로 차단된 프레임은 관측 miss 한 프레임으로 처리하며 모든
  트랙을 즉시 초기화하지 않습니다. 혼합 프레임에서는 차단된 트랙만 숨기고 노화시킵니다.

현재 drop 이벤트는 `PresenceFusion`이 소비합니다. 확인된 퇴실 drop은 해당 소실에
대한 새로운 LD2410C hold를 막습니다.

## 4. 재실 융합

PIR과 LD2450은 서로 보완하는 재실 획득 근거입니다. PIR 움직임 또는 confirmed/coasting
트래커 결과가 base presence를 유지할 수 있습니다. 프레임 전체가 필터로 차단되지 않는
한 움직임은 PIR 움직임과 트래커 움직임의 OR입니다.

LD2410C 보조 규칙은 다음과 같습니다.

- 하드웨어가 없으면 `available: false`로 조용히 무시합니다.
- LD2410C 단독으로 재실, 움직임, 타깃 개수, 방·구역 상태 또는 히트맵을 만들지
  않습니다.
- 기존 PIR/트래커 세션과 정적 레이더 재실이 2초 동안 겹쳐야 보조가 armed됩니다.
- 확인된 퇴실 근거 없이 LD2450이 사라지면 armed된 LD2410C가 재실을 유지할 수
  있습니다.
- 퇴실/filter veto 없이 안정화 재실이 끝나면 이미 armed된 보조에 한해 30초 동안
  같은 세션의 재진입 기회를 한 번 허용합니다.
- PIR 또는 LD2450이 다시 감지되면 primary/secondary 전환 없이 원래의 결합 근거로
  돌아갑니다.

표시 목적으로만, 보조가 명확한 단일 confirmed/coasting LD2450 트랙의 마지막
좌표를 유지할 수 있습니다. 이 좌표는 활성 타깃이 아니며 타깃 개수, 방, 구역, 보정,
히트맵 계산에서 제외합니다.

## 5. 정적 레이더 거리 안정화

held-target 표시 신뢰도에는 LD2410C의 `detectionDistanceMm`만 사용합니다.

- 1초에 최대 한 개의 유효 거리만 최근 3개 중앙값 이력에 넣습니다.
- 첫 유효 샘플은 즉시 표시합니다.
- 한 번의 튐은 안정값을 바꾸지 못합니다.
- 정적 재실이 유지되는 동안 짧은 유효하지 않은 거리값은 마지막 안정값을
  유지합니다.
- 정적 재실이 해제되거나 센서가 사용 불가가 되면 거리 이력을 초기화합니다.
- 이동/정지 거리와 energy는 원시 진단값이며 위치 추론에 조합하지 않습니다.

## 6. 검증과 한계

- 네이티브 테스트는 생명주기, assignment, Kalman smoothing, 퇴실/방 drop, 융합
  arming, exit veto, 재진입, 하드웨어 없음, held-target 신뢰도와 거리 안정화를
  비롯해 필터 타깃과 admission 타깃이 섞인 상황을 다룹니다.
- 리플레이 로그는 raw 관측, production 필터 관측, 트래커 출력, 퇴실 근거,
  정적 레이더 입력과 융합 상태를 구분합니다.
- BLE nearby와 수면 시간 설정은 재실 획득 근거가 아닙니다.
- 트랙 정책 상수와 LD2410C 거리 일치는 다양한 실제 설치 환경에서 계속 검증해야
  합니다.
